# HomeRadar: экспорт в формате Apify

Парсер Яндекс Карт с экспортом под согласованный формат HomeRadar.

**Запуск и контракт HomeRadar: [HOMERADAR.md](HOMERADAR.md).**
Новый сценарий `export_homeradar.py` запускает существующий сборщик, дополняет данные
аватарами и ответами организаций из публичных страниц и сохраняет JSON-массив с девятью
полями Apify. При ошибке, неполном сборе или расхождении данных готовый файл не заменяется.
Интеграция WordPress и действующая Apify-интеграция не изменены.

Ниже — документация сборщика.

# 🗺️ Yandex Maps Reviews

Поиск организаций по территории и категориям, сбор отзывов, звёзд и общих оценок с Яндекс Карт. Данные доступны как связанные таблицы Pandas, точки GeoPandas и JSON-файлы.

- Выбор территории: город из локального каталога, прямоугольник или GeoJSON.
- Сбор всех доступных отзывов либо заданного числа самых свежих на каждую организацию.
- Сохранение прогресса, повторный запуск и явные признаки полноты данных.

**API и ключи доступа Яндекса не нужны:** сбор выполняется через публичные страницы в Chromium. Примеры вывода ниже используют **вымышленные данные**; реальные названия, объём и оценки зависят от выбранной территории.

## 🐍 Собрать организации и отзывы

```python
# Импортируем функцию сбора.
from yandex_maps_reviews import collect_area
# Ищем кафе и жилые комплексы; получаем до 50 свежих отзывов каждой организации.
result = collect_area(city="Москва", tags=["cafe", "residential"], max_orgs=3, max_reviews=50, output="results_moscow")
# Показываем основные сведения о найденных организациях.
print(result.organizations[["organization_id", "name", "rating", "review_status"]].head(3).to_string(index=False))
```

Пример таблицы организаций:

```text
organization_id          name  rating review_status
            101 Кафе «Пример»     4.7      complete
            202   ЖК «Пример»     3.8       stalled
```

```python
# Показываем тексты, звёзды и признак подтверждения каждой записи.
print(result.reviews[["organization_id", "text", "rating", "confirmed"]].head(3).to_string(index=False))
```

Пример таблицы отзывов:

```text
organization_id                   text  rating  confirmed
            101          Вкусный кофе.       5       True
            101 Уютно, но долго ждали.       4       True
            202   Не хватает парковки.       2      False
```

Таблицы связаны строковым `organization_id`. В `organizations.rating` находится общая оценка организации, в `reviews.rating` — звёзды конкретного отзыва. Даты отзывов доступны в UTC (`date`) и в исходном виде (`date_raw`). Неизвестные значения остаются пропусками.

```python
# Отбираем подтверждённые полные тексты с датой и звёздами 1–5.
confirmed = result.confirmed_reviews()
# Считаем записи, пригодные для анализа в приведённом примере.
print(len(confirmed))
```

```text
2
```

Строка с `confirmed=False` сохранена для прозрачности результата, но в эту выборку не входит. Причина доступна в `observation`, `full_text_confirmed` и диагностике `result.metadata`.

```python
# Создаём точки организаций в WGS84.
geo = result.to_geopandas()
# Показываем идентификаторы и координаты точек.
print(geo[["organization_id", "geometry"]].head(3).to_string(index=False))
```

```text
organization_id            geometry
            101 POINT (37.62 55.75)
            202 POINT (37.63 55.76)
```

Неизвестные координаты дают отсутствующую геометрию. Отзывы остаются в отдельной таблице.

### 💾 Сохранить организации с отзывами в GeoJSON

```python
# Сохраняем все организации; у каждого объекта — свои оценки, отзывы и координаты.
print(result.save_geojson("organizations.geojson"))
# По желанию исключаем неподтверждённые отзывы, сохраняя все организации.
print(result.save_geojson("confirmed.geojson", confirmed_only=True))
```

```text
organizations.geojson
confirmed.geojson
```

Одна организация — один `Feature`, её отзывы вложены в `properties.reviews`. Ниже сокращённый пример одного объекта; в файле также сохраняются остальные поля и признаки полноты.

```json
{
  "type": "FeatureCollection",
  "features": [{
    "type": "Feature",
    "id": "101",
    "geometry": {"type": "Point", "coordinates": [37.62, 55.75]},
    "properties": {
      "organization_id": "101",
      "name": "Кафе «Пример»",
      "rating": 4.7,
      "review_status": "complete",
      "reviews": [{"text": "Вкусный кофе.", "rating": 5, "confirmed": true}]
    }
  }]
}
```

Для словаря Python без записи файла используйте `result.to_geojson()`. Экспорт не требует GeoPandas; неизвестное положение сохраняется как `geometry: null`. Фильтрация отзывов не меняет исходный статус полноты.

## 📍 Другие способы выбора территории

Передайте **ровно один** параметр: `city`, `bbox`, `geometry` или `config`.

```python
# Прямоугольник с карты: запад, юг, восток, север, в градусах WGS84.
result = collect_area(bbox=[84.965, 56.455, 85.005, 56.485], tags=["cafe"], max_reviews=50, output="results_rectangle")
# Полигон из своего файла; вместо пути также допустим словарь GeoJSON.
result = collect_area(geometry="district.geojson", tags=["residential"], max_reviews=50, output="results_polygon")
# Территория и категории, экспортированные интерфейсом карты.
result = collect_area(config="area.json", max_reviews=50, output="results_from_map")
```

Каждый вызов возвращает тот же объект с `organizations`, `reviews` и `metadata`. Используйте подходящий вам вариант. Для GeoJSON допустимы Polygon, MultiPolygon и полигональные коллекции; проверяются точные контуры и отверстия.

По названию пока доступны **Москва и Санкт-Петербург**. В комплекте архивные границы OSM от **8 декабря 2016 года**; для актуальной территории загрузите свой GeoJSON. Для прямоугольника пары «широта, долгота» из некоторых карт нужно переставить в порядок «долгота, широта».

### 🗺️ Выбрать территорию на карте

```bash
# Открываем локальный интерфейс выбора территории.
python -m http.server 8000 --bind 127.0.0.1
```

1. Откройте [карту](http://127.0.0.1:8000/select_area.html).
2. Нарисуйте прямоугольник или полигон, загрузите GeoJSON либо выберите город.
3. Найдите и отметьте категории; при необходимости добавьте свои поисковые запросы.
4. Скачайте `area.json` и передайте его функции, как в примере выше.

Сервер используется только для выбора территории. Подложка карты — OSM; организации и отзывы собираются с Яндекса.

## ⚙️ Основные параметры

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `tags`, `queries` | Из конфига или не заданы | Категории и свободные запросы; нужен хотя бы один |
| `max_orgs` | `20` | Максимум организаций на каждый запрос, от 1 до 100 |
| `max_reviews` | `None` | Все доступные отзывы; `50` — до 50 самых свежих на организацию |
| `with_reviews` | `True` | `False` — только поиск организаций |

## 💾 Сохранение и повторный запуск

- Повторите вызов с той же папкой и параметрами, чтобы продолжить сбор или использовать готовый кэш.
- Для другой территории используйте отдельную папку.
- Частичный снимок сохраняется, но не считается готовой полной выборкой.

```python
# Читаем сохранённые таблицы без обращения к Яндексу.
from yandex_maps_reviews import load_results
# Выбираем тот же лимит, с которым выполнялся сбор.
saved = load_results("results_moscow", max_reviews=50)
# Показываем размеры таблиц для вымышленного примера выше.
print({"organizations": len(saved.organizations), "reviews": len(saved.reviews)})
```

```text
{'organizations': 2, 'reviews': 3}
```

| Файл в папке результата | Содержимое |
|---|---|
| `organizations.json` | Организации, территория и состояния поисков |
| `reviews/<id>.json` | Снимок отзывов без заданного лимита |
| `reviews/<id>.limit50.json` | Снимок для лимита 50; число в имени соответствует лимиту |
| `search/`, `review_jobs.json` | Поисковые кандидаты, диагностика и прогресс очереди |

## 🔗 Сбор по известной карточке

Если ссылка или идентификатор уже известны, можно обойтись без поиска территории:

```bash
# Получаем до 50 свежих отзывов одной организации.
python collect_yandex.py 44307431220 --limit 50 --output reviews_one
```

Пример итоговой строки терминала; перед ней могут выводиться сообщения о ходе сбора:

```json
{"organization_id": "44307431220", "status": "capped", "valid_reviews": 50, "truncated_count": 0, "elapsed_seconds": 12.34, "scrolls": 1, "expanded_texts": 2}
```

Файл появится в `reviews_one/44307431220.limit50.json`. Вместо числа можно передать полную HTTPS-ссылку на карточку `yandex.ru` или `yandex.com`; несколько карточек обрабатываются последовательно. `load_results()` предназначен для результатов поиска территории; отдельные файлы карточек читаются как JSON.

Сбор по экспорту карты также доступен из терминала:

```bash
# Находим организации и собираем до 50 отзывов каждой по выбору из area.json.
python discover_yandex.py --config area.json --with-reviews --review-limit 50
```

Результат — папка `review_results` со структурой из таблицы выше. Для всех доступных отзывов уберите `--limit` или `--review-limit`.

## 🚦 Как оценить полноту результата

| Состояние карточки | Значение |
|---|---|
| `complete` | Получены полные записи в объёме счётчика страницы |
| `capped` | Получен заданный максимум полных отзывов |
| `stalled`, `incomplete_fields`, `count_mismatch` | Снимок частичный либо противоречивый; смотрите диагностику |
| `captcha`, `rate_limited`, `access_denied` | Сайт ограничил доступ; очередь остановлена |

Для анализа используйте `confirmed_reviews()` и проверяйте `organizations.reviews_ready`. Прежние неподтверждённые записи отмечаются как `observation="previous_snapshot"`; их наличие в файле не означает, что они заново получены. При явно частичном исходе `collect_area()` возвращает `metadata["run_status"]="partial"`; ошибка параметров или процесса вызывает исключение.

Сбор охватывает **видимую поисковую выдачу**, а не гарантированный полный каталог города. Оценки без текстового отзыва не входят в число собранных отзывов. CAPTCHA автоматически не решается; ограниченные повторы после HTTP 429 учитывают `Retry-After`. Паузы не гарантируют отсутствие блокировки. Остальные статусы и действия — в [инструкции](docs/USAGE.md#статусы-и-диагностика).

# HomeRadar — замена выгрузки Apify

## Установка

Нужен Python 3.11+. Зависимости перечислены в `pyproject.toml`.
В PowerShell из папки репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install .
.\.venv\Scripts\python.exe -m playwright install chromium
```

## Собрать организацию и получить файл для проверки импорта

```powershell
.\.venv\Scripts\python.exe export_homeradar.py 79619695705 --output review_results/homeradar/79619695705.json
```

Вместо ID можно передать полную HTTPS-ссылку на организацию в `yandex.ru/maps/org/…`.
Если используется установленный Google Chrome:

```powershell
.\.venv\Scripts\python.exe export_homeradar.py 79619695705 --output review_results/homeradar/79619695705.json --executable "C:\Program Files\Google\Chrome\Application\chrome.exe"
```

Готовый файл: **`review_results/homeradar/79619695705.json`**.
Каждый запуск заново проверяет карточку (`--refresh` исходного сборщика), а не выдаёт вчерашний кэш.
Код выхода `0` и событие `homeradar_export` означают успешный экспорт текущего запуска.
При ненулевом коде выхода прежний файл может существовать: это не результат текущего запуска,
его нельзя считать свежим или автоматически импортировать после ошибки.

## Контракт импорта

Корень — JSON-массив. Каждая запись содержит ровно эти девять полей:

```json
[
  {
    "businessRating": 4.7,
    "businessRatingsCount": 499,
    "text": "Вымышленный пример отзыва.",
    "rating": 5,
    "date": "2026-10-01T12:00:00Z",
    "authorName": "Тестовый автор",
    "authorAvatarUrl": "",
    "businessComment": "Спасибо!",
    "businessCommentDate": "2026-10-02T12:00:00Z"
  }
]
```

- `businessRating` — общий рейтинг Яндекса с точностью до одного десятичного знака,
  не среднее по скачанным отзывам.
- `businessRatingsCount` — общее количество **оценок**, не число текстовых отзывов.
- Общие показатели повторяются в каждом элементе, поскольку импортёр читает их из первого.
- Даты — ISO 8601 UTC; используется `updatedTime` источника (дата последнего изменения).
- Отсутствующие аватар и ответ — пустые строки; существующие ответы и аватары не заменяются заглушками.
- В массив не добавляются служебные ID, статусы или другие поля вне согласованного контракта.
  При импорте организация определяется сохранённым в WordPress ID Яндекс Карт,
  соответствующим ID в команде запуска.

## Что адаптировано

Сбор остаётся в `collect_yandex.py` исходного проекта. Он использует Playwright/Chromium,
сохраняет прогресс и признаки полноты. `export_homeradar.py` не заменяет его новым парсером:

1. Запускает оригинальный сборщик, сохраняя его вывод и диагностику.
   При полном сборе не переключает меню сортировки: полный набор упорядочивается локально по датам.
   Выбор сортировки на сайте сохранён для ограниченной выборки самых свежих отзывов.
2. Читает публичное HTML-состояние страниц отзывов для получения аватаров и ответов с датами.
   Это не официальный API. Используется существующий `StateScript`, а не второй HTML-парсер.
3. Проверяет пагинацию, количество отзывов, ID организации, уникальность исходных ID и общие показатели.
4. Сопоставляет каждый отзыв по исходному ID, а если ID в DOM отсутствует — по полному тексту,
   оценке, автору и дате. Неоднозначное сопоставление завершает экспорт ошибкой.
5. Записывает массив существующей атомарной функцией `storage.save_result` только после всех проверок.
   Существующая блокировка `storage.output_lock` исключает одновременные экспорты в одну папку.

Служебные данные остаются рядом с выгрузкой:

```text
review_results/homeradar/
  79619695705.json
  work/79619695705/
    raw/79619695705.json
    raw/review_jobs.json
    public-details.json
```

Весь `review_results/` исключён из Git: реальные отзывы, локальные пути и диагностические файлы
не публикуются с исходниками. В тестах используются только вымышленные отзывы.

## Безопасное обновление

При CAPTCHA, HTTP 403/429, незавершённом сборе, дубликатах, отсутствующих обязательных полях,
неоднозначном сопоставлении и изменении показателей между проходами команда завершается ошибкой.
HTTP 429 не повторяется автоматически. Для дополнительных HTML-страниц предусмотрена пауза 1 секунда
и предел 12 страниц; сетевой запрос ограничен 30 секундами, браузерный процесс — 15 минутами.
Неполная выгрузка не публикуется даже если Яндекс ограничивает доступное число отзывов.

Карточка без отзывов тоже не перезаписывает готовый файл: `[]` не может передать рейтинг и число оценок
импортёру, который читает их из первого элемента. Для такого случая нужен отдельно согласованный
контракт WordPress. Отсутствующий общий рейтинг не подменяется нулём.

Для ежедневного обновления планировщик должен запускать эту же команду вне HTTP-запроса посетителя
и передавать файл импортёру **только после кода выхода 0**. При ошибке ранее импортированные отзывы
должны сохраняться. Сам JSON не содержит стабильных ID отзывов, поэтому правила дедупликации и
обновления на стороне WordPress необходимо согласовать с разработчиком сайта.

Расписание, транспорт передачи JSON и запись в WordPress здесь не добавлялись:
в переписке согласован только формат; код и endpoint импортёра не предоставлены.
Перед заменой Apify нужно проверить даты, обновление и сохранность прежних отзывов на тестовой копии.

## Повторить экспорт сохранённых данных без сети

```powershell
.\.venv\Scripts\python.exe export_homeradar.py 79619695705 --from-snapshot review_results/homeradar/work/79619695705/raw/79619695705.json --details review_results/homeradar/work/79619695705/public-details.json --output review_results/replay/79619695705.json
```

Этот режим не делает данные свежими; он предназначен для проверки адаптера и воспроизводимости.

## Тесты

Только адаптация, без сети и браузера:

```powershell
.\.venv\Scripts\python.exe -m unittest test_homeradar -v
```

Все тесты, включая исходные проверки в браузере на локальном HTML:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
```

Если вместо браузера Playwright используется установленный Chrome, перед полным прогоном задайте:

```powershell
$env:REVIEW_CHROMIUM_PATH = "C:\Program Files\Google\Chrome\Application\chrome.exe"
```

## Ручная проверка на GitHub Actions

Вкладка **Actions → HomeRadar manual smoke test → Run workflow** запускает
локальные регрессионные тесты на Ubuntu 24.04 и реальный CLI для десяти фиксированных
организаций из предыдущей проверки (`actions_smoke.CASES`). Карта и секреты сайта не используются.

Это только ручная проверка, без расписания, развёртывания и отправки в WordPress.
При CAPTCHA/HTTP 403/429 оставшаяся очередь останавливается.
Готовые JSON повторно сверяются существующим валидатором `build_export` с исходными данными.
Неполная выгрузка считается провалом, а не успешным пустым результатом.
Поэтому две ранее неподдержанные карточки также могут сделать весь workflow красным.

Публичный артефакт `homeradar-smoke-summary` содержит только количество записей,
общие показатели, длительность и статусы. Тексты отзывов, авторы, аватары и исходные логи
остаются в `review_results/` на временной машине runner и не загружаются в артефакты.
Сводка хранится три дня. Полные результаты с runner автоматически на сайт не передаются.
